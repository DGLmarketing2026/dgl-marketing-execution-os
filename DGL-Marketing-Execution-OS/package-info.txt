========================================================================
DGL MARKETING EXECUTION OS — PACKAGE INFO
========================================================================

Nombre del proyecto : DGL Marketing Execution OS
Cliente interno      : Dedicated Ground Logistics (DGL) — Freight Broker (3PL)
Tipo de entregable    : Plataforma web SaaS interna (HTML / CSS / JavaScript)
Stack técnico         : HTML5, CSS3 (custom design system), JavaScript ES6 (vanilla,
                         sin frameworks ni build step), Chart.js 4.x (CDN),
                         Lucide Icons (CDN), Google Fonts — Inter (CDN)
Requiere instalación  : No. Se abre directamente en navegador (index.html).
Requiere backend      : No en esta versión (datos de muestra). Preparado para
                         conectarse a Salesforce / Nova / CRM en una fase futura.
Compatibilidad        : Chrome, Edge, Firefox, Safari (últimas 2 versiones).
Responsive            : Desktop XL / Laptop / Tablet / Mobile.

------------------------------------------------------------------------
ARQUITECTURA
------------------------------------------------------------------------

La plataforma es una Single Page Application (SPA) sin build step:

  index.html
    → carga assets/css/*.css (sistema de diseño + responsive)
    → carga assets/js/data.js (datos de muestra, única fuente de verdad)
    → carga components/*.js (builders de UI reutilizables: kpi cards,
      campaign cards, tablas, modales, filtros, sidebar, header)
    → carga assets/js/charts.js (wrappers de Chart.js con tema DGL)
    → carga assets/js/modules.js (16 módulos funcionales — cada uno
      registra su renderer en window.DGL_MODULE_RENDERERS)
    → carga assets/js/interactions.js (modales de detalle, filtros,
      búsqueda global, toasts, colapso de sidebar, navegación mobile)
    → carga assets/js/app.js (router basado en hash + ensamblaje del
      shell — sidebar + header + main content)

Navegación: basada en #/id-de-modulo (ej. #/reactivation). Al cambiar el
hash, app.js destruye el contenido anterior, limpia los charts activos
(assets/js/charts.js mantiene un registro de instancias) y renderiza el
nuevo módulo. Esto evita fugas de memoria y errores de "canvas reused".

------------------------------------------------------------------------
CARPETAS
------------------------------------------------------------------------

/assets/css   → Sistema de diseño (variables de marca, componentes,
                dark mode, glassmorphism) + capa responsive.
/assets/js    → Lógica de datos, gráficos, módulos, interacciones y
                router.
/components   → Funciones puras que devuelven HTML (string templates)
                reutilizadas por múltiples módulos: KPI cards, campaign
                cards, tablas inteligentes, modales, filtros, sidebar,
                header.
/data         → Espejo en JSON puro de los datos de muestra, útil para
                integraciones futuras, pruebas o importación a otras
                herramientas (BI, hojas de cálculo, scripts de
                migración a CRM real).

------------------------------------------------------------------------
NOTA SOBRE LOS DATOS
------------------------------------------------------------------------

Todos los registros (cuentas, cotizaciones, campañas, secuencias de
email, playbooks, assets, cuentas ABM, KPIs) son SAMPLE DATA — datos
simulados que representan de forma realista la operación de un Freight
Broker en Norteamérica. Ningún dato corresponde a clientes reales de
DGL. Están señalizados en la interfaz con la etiqueta "Sample Data".
